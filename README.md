# PrintMO-Wholesale-API-Integration

## Order Manager S&S submission

`POST /order-manager/v1/supplier/ss/commit` validates aggregate SKUs and makes one S&S order POST. In the `testOrder` order-placement workflow it skips optional per-SKU price lookups, leaving the estimated subtotal null; a large batch otherwise consumes S&S's 60-requests-per-minute API budget before the POST. For a future non-test submission, transient product-price lookup failures receive at most three retries across the entire batch; if pricing is still unavailable, the gateway sends the order with a null estimated subtotal and a SKU-scoped price warning. A failure before the order POST returns `orderSubmissionAttempted: false`, while a failure during or after it returns `true`. The Order Manager uses that marker to distinguish a retryable preflight failure from an uncertain result. The gateway never retries an order POST. The Worker controls `testOrder`; this change does not enable live purchasing.

Response mapping selects the documented `sku` before numeric `skuID` independently of JSON property order. An ID-only response stays ID-only; it is never guessed into a SKU. Missing, null and blank quantities remain missing, while explicit zero remains zero. The additive `acceptanceEvidence` distinguishes native line quantities from summary-derived request quantities. Synthetic contract tests run as part of `npm test`.

The supplier operation is the Orders API POST in either mode; `testOrder` is not a website-cart operation. The gateway does not automate the owner's manual cancel/add-back-to-cart step.

Supplier errors preserve the actual `upstreamHttpStatus` separately from the gateway HTTP status (for example, upstream 503 with gateway 502), the bounded native message/code, and `responseBodyFormat`. Non-JSON replies receive an explicit safe fallback; their raw body and headers are never returned. `orderSubmissionAttempted` remains the evidence for whether the order POST began; this change does not retry it or alter supplier flags/payloads.

Only the exact native JSON 503/code 503 message `You are being throttled. Please wait 1 minute before your next request.` (whitespace normalized), without returned orders/references or positive accepted quantities, is classified as `failureKind: rate_limited` with `outcome: rejected`. This is a narrow operational inference, not a guarantee that no order exists: `orderSubmissionAttempted` stays true and the gateway never retries the POST. `retryAfterSeconds` is at least 60 and `retryAt` is anchored to `upstreamResponseAt`; valid Retry-After and X-Rate-Limit-Remaining values are the only captured response-header metadata. Generic/HTML/contradictory 503s stay unknown. The test-only `scripts/fixtures/supplier-commit-app.js` adapter registers the actual Express commit handler with a mocked native transport for local integration fixtures.

## Read-only S&S inventory gateway

Repeated `DS` rows in product warehouse metadata are accepted only when every repeated flag is `dropship: true`. Physical warehouse duplicates, conflicting flags, and duplicate inventory quantity rows still fail the read. DS quantities remain excluded from the Worker's physical stock count.

`GET /order-manager/v1/supplier/ss/inventory?skus=SKU1,SKU2` serves the separate inventory observation Worker. Set `INVENTORY_READ_KEY` on Render and send it in `X-Inventory-Read-Key` so the Worker has access only to this read route. Until that key is configured, the route retains its existing `X-Order-Manager-Key` authentication for a staged deployment; once configured, the admin key no longer authenticates this route. The gateway holds `SS_ACCOUNT_NUMBER` and `SS_API_KEY` server-side. Requests must contain 1–25 distinct S&S SKUs. The response contains only `observedAt` and `items` with `sku` and warehouse rows of `warehouseAbbr`, nonnegative integer `qty`, and boolean `dropship`; it is marked `Cache-Control: no-store`. Missing supplier rows remain missing, and upstream errors never become zero stock.

The route makes two bounded S&S GETs: inventory for quantities and products for warehouse dropship flags. It joins exact SKU and warehouse codes, rejecting missing or malformed matches. The Worker excludes DS and every `dropship: true` row from physical warehouse stock. The route does not update Shopify, place supplier orders, or use Redis. `observedAt` is the gateway fetch time, not an S&S source timestamp. Run `npm test` before deploying this shared service; it includes the existing phase-two checks and focused inventory-route checks. After deployment, verify the existing order routes and make one authenticated inventory read before enabling the separate Worker's dry-run schedule. The route code alone does not deploy the service.
